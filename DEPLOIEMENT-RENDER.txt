Le site v2 tourne avec Node 22.13+ (base SQLite intégrée, aucune
dépendance npm). Il a besoin de TROIS réglages sur Render.

----------------------------------------------------------------
ÉTAPE 1 — CRÉER LE SERVICE (Blueprint)
----------------------------------------------------------------
1. https://dashboard.render.com → "New +" → "Blueprint".
2. Sélectionner le dépôt elite-football-academy → "Apply".
   Render lit render.yaml : Node 22.23, commande de démarrage
   "node --no-warnings server.js", variable DATA_DIR=/var/data.

   À la main (si Blueprint échoue) : "New +" → "Web Service" →
      Runtime Node · Build Command vide ·
      Start Command : node --no-warnings server.js ·
      Environment : NODE_VERSION=22.23.2, DATA_DIR=/var/data,
      ADMIN_PASSWORD=(voir étape 2)

----------------------------------------------------------------
ÉTAPE 2 — MOT DE PASSE DE LA DIRECTION
----------------------------------------------------------------
Service → "Environment" → ADMIN_PASSWORD = un mot de passe solide
(12 caractères minimum). C'est le mot de passe du compte
"direction" sur …/connexion. Il n'est écrit nulle part dans le
code : si la variable est absente, le compte démarre avec
"Elite2026" et IMPOSE son changement à la première connexion.

----------------------------------------------------------------
ÉTAPE 3 — PERSISTANCE DES DONNÉES (indispensable en production)
----------------------------------------------------------------
Sur le plan GRATUIT, le disque de Render est effacé à chaque
redéploiement ou réveil après mise en veille : joueurs, comptes
parents, présences et paiements disparaîtraient. Ce n'est pas un
bug du site : c'est la règle de l'hébergeur.

Deux solutions :
  a) Plan payant "Starter" + disque persistant :
     Service → "Disks" → Add Disk : name elite-data,
     mount path /var/data, 1 GB. (Ou décommenter le bloc "disk"
     de render.yaml.) La base SQLite vit alors sur ce disque.
  b) Rester gratuit et accepter le risque, en faisant un EXPORT
     régulier : Espace direction → Paramètres → "Exporter la
     sauvegarde" (fichier JSON complet, restaurable au même
     endroit). À faire après chaque journée de saisie.

Vérifié localement : avec DATA_DIR pointant sur un dossier
conservé, toutes les données ET les sessions ouvertes survivent
à un redémarrage du serveur (test automatisé tools/test-api.mjs).
Sur Render, cette persistance dépend du disque de l'étape 3a.
